# overclaim replay

`replay.py` replays the labeled Claude Code trials published by
[overclaim](https://github.com/h-a-forster/overclaim) (MIT) through prog's real
shims and stop hook. It answers one preregistered question (#303, H1): does
prog's stop gate block the runs that failed their hidden checks more often
than it blocks correct work?

Each trial gets a fresh copy of its task repo, a fresh store and isolated XDG
dirs. The `prog` binary you pass runs the plugin's hooks exactly as Claude Code
would: `SessionStart` installs the default shims; every test command in the
transcript goes through the real `python`/`pytest` shim, with a stand-in
interpreter that prints the recorded output; `PostToolUse` follows every shell
call; one `Stop` carries the trial's final message with `PROG_STOP_GATE=1`.
Nothing is sent anywhere and no model is called.

## Reproduce

```sh
git clone https://github.com/h-a-forster/overclaim && git -C overclaim checkout dcebc5f
mkdir data && cd data
gh release download results-data -R h-a-forster/overclaim
shasum -a 256 -c SHA256SUMS
for run in setups setups-rerun interventions; do
  mkdir -p ../x/$run && tar -xzf $run-transcripts.tar.gz -C ../x/$run
done
cd ..
python3 -I path/to/prog/scripts/overclaim-replay/replay.py \
  --overclaim overclaim --transcripts x --prog "$(command -v prog)" \
  --out-dir results
```

It takes about three minutes on eight cores. `--limit N` replays the first N
trials of each run. `--model-git-stash` is a variant that is not
preregistered: it runs each call's `git stash` / `git stash pop` in the
workspace, so a revert check really runs on reverted content.

## Results

- [results/report.md](results/report.md): the preregistered replay with
  `prog 0.2.0`, generated by the script; `results/rows.jsonl` has one row per
  trial (no message text).
- [results/stash-0.2.0.md](results/stash-0.2.0.md) and
  [results/stash-branch.md](results/stash-branch.md): the `--model-git-stash`
  variant with `prog 0.2.0` and with the stop gate's two changes in the
  CHANGELOG's Unreleased section (the run on the current content decides after
  a revert check; an earlier failure stays open until a run names it passing).

The reports list every fidelity limit and every harness correction made after
the first full run. Do not edit them by hand; rerun the script.
